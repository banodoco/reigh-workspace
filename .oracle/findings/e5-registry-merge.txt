Findings (ranked):

1. **The seam is real and currently unimplemented.** `save()` is whole-replace: CAS at `repository.py:995,1013-1019`, then updates **both** `document_json` + `asset_registry_json` (`:1026-1032`). The editor's save payload is `(config, registry, expected_version)` (`:146-148`) — a stale editor save would silently revert any completed-generation registry entry. No merge path exists yet (`grep record_completion|registry_merge` → 0 hits in Astrid-oracle).
2. **New event kind is legal; reuse of `timeline.saved` is not viable.** Kinds are validated against the frozen pack manifest (`core/events/registry.py:352-367`); doc 18 §16-Q2 rules: "a new kind is a schema-pack change; the wire contract is neutral." `timeline.saved`'s payload contract is the full-document delta (`repository.py:86-92`); a merge has no document, so reusing it breaks event-log reconstructability. Adding one line to `astrid/packs/timeline/schema-pack.yaml:24-28` suffices — in-tree, forward-only, no migration.
3. **Merge must mutate `asset_registry_json` only.** `show` already derives `config_version` purely from `head_seq` (`:1750-1759`), so leaving `document_json` byte-identical while advancing the head preserves one-CAS-version semantics — exactly doc 27 §7.1's ban on layered CAS objects. Archive fence must be honored (`:997-1005`).
4. **Concurrency resolves by serialization, no LWW.** Both paths go through the one writer queue: editor-first ⇒ merge applies atop the editor's fresh registry; merge-first ⇒ editor save gets a genuine `409` carrying the new head (matches engineering-answers/A.rtf:147-149). Message.txt:53 mandates proving this with a save-storm fixture; any silent loss is an architecture stop.

**Recommended design:** add `timeline.registry_merged` to `schema-pack.yaml` event_kinds (no new command kind — the merge takes no receipt of its own). New `TimelineRepository.merge_registry(uow, *, project_id, timeline_id, entries) -> int`: inside the completion UoW's `BEGIN IMMEDIATE`, read stream head + current `asset_registry_json`, additive upsert (new media-id keys only), append one hash-chained `timeline.registry_merged` with payload `{assets: merged, added_keys, base_head}` via the existing `_events.append(expected_head_seq=current_head)`, advance both heads; return new head into the `generation.record_completion` receipt result. No caller-supplied `expected_version` — "against the current head" per docs 17 §5/27 §5; replay safety comes free from the completion receipt. Always append (even no-op deltas) for deterministic audit.
