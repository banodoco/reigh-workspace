# Integration & E2E manager goal

Prepare the receiving manager for one bounded Integration & E2E project in the
Astrid portfolio. The canonical active run, once the orchestrator activates this
receiver, is `.otto/runs/astrid-integration-e2e-20260910/` at the workspace
root. This handover is the portable seed; it is not a second live run.

Direction: [northstar.md](northstar.md). Sole role/stage/budget declaration:
[run.yaml](run.yaml). Approach: [plan.md](plan.md). Assignments:
[tasklist.md](tasklist.md). Current state: [status.md](status.md).

## Scope and authority

The manager owns only:

- a thin source/dependency manifest and integration checklist;
- read-only discovery of existing supported setup, startup, discovery,
  authentication, test and evidence entry points;
- continuous assembly of code-ready upstream handoffs at accepted seams;
- one practical final CPU/local setup/workflow receipt on the settled
  composition; and
- normal final merge/push coordination and final-main identity verification,
  returning evidence to the portfolio orchestrator for META-5/META-6.

The six project managers retain implementation custody, their original task and
criterion IDs, and their configured owning reviews. Integration routes defects
back to those owners. It does not implement publication, recovery, session,
schema, lifecycle or visualization behavior, and it does not create a second
review panel, oracle pool, queue, database, migration, deployment or provider
adapter.

Preparation is `planning_only`: do not launch agents, mutate product source or
live realms, run a product workflow, spend money, merge, push, deploy, migrate
old data, or perform git actions in this preparation turn. The receiving mode is
delivery under the portfolio [authority](../../authority.md) once activated by
the orchestrator. The receiver must first recover the existing unified-execution
manager's exact P7 handoff; it must not recreate that manager or infer source
identity from historical records.

## Required outcome

On activation, deliver a compatible multi-repository composition, a reproducible
supported setup/workflow receipt, and a verified final-main manifest. The source
universe is the actual UE handoff across Astrid, Banodoco Workspace Runtime,
Reigh app, Reigh worker and VibeComfy. The workspace host
(`banodoco/reigh-workspace`, this control checkout) is coordination/control
storage, not an aggregate source repository and not a substitute for any of
those repositories.

The final journey must consume the six accepted project results and their
original review receipts: upstream reviews gate code-ready handoffs, while any
owning final review that requires INT-03 evidence occurs after that campaign and
before INT-04. It includes the V1 fixture-ready prerequisite before UX-01/E2-06
consumption; Integration verifies that fixture can be installed and used but
does not build it. E2's durable/shared-byte protection is demonstrated only with
disposable lifecycle objects. A successful synthetic CPU journey does not close
missing UE physical/GPU, credential, capture, fixture or owning-review evidence.
