# Twelve-hour course-correction oracle

The user explicitly authorizes a substantive GPT-6 Astra oracle checkpoint every 12 hours while portfolio delivery remains active. Resolve the model/reasoning through run.yaml's `periodic_oracle.role` → `roles.oracle` (currently Astra high). This is a course-correction decision, not a product acceptance review, another implementation manager or a replacement for the hourly per-project Luna investigators.

## Clock and accounting

At destination bootstrap, a delegated recorder saves `started_at_utc` once in status.md. Each hourly update records `observed_at_utc`, completed elapsed wall-clock hours since that start, actual hourly checkpoints completed, and next 12-hour boundary. These are distinct counters: downtime and late check-ins count as elapsed time, not fabricated observations. Preserve the original start and counters across resumes; do not reset the clock when a manager restarts.

At the first check on or after hour 12, 24, 36 and so on, run the scheduled oracle checkpoint. If several intervals were missed, perform one coalesced checkpoint covering the gap, record the missed boundaries, then set the next due boundary to the next multiple of 12 after current elapsed time. Do not launch a burst of catch-up calls. The existing same-thread wakeup-loop detects due work; no new scheduler, background watcher or hourly polling script is created. If delivery completes or the user stops it, no further scheduled calls are due.

The explicit `periodic_oracle` allowance is **one oracle invocation per due/coalesced checkpoint**, authorized separately from the existing three total ad-hoc meta-oracle responses. Preserve and report both counts independently. This latest override supersedes older prose saying all meta-oracle use shares three total responses; it changes no project-local oracle/review/GPU budget. Do not repurpose an unused periodic slot for unrelated questions, stack a reassurance call onto it, or label an extra review as this checkpoint. Follow-up decision calls use the remaining ad-hoc allowance or require user authorization. Record invocation identity/time/status before dispatch; recover interrupted calls before retrying and conservatively charge uncertain invocations. A missing/failed response is a visible evidence gap, not a successful checkpoint or an automatic extra paid retry.

## Assemble an informed, bounded packet through agents

Use the current hourly project investigators' reports, not another investigation swarm. A delegated recorder prepares a source-identified input manifest under `local/oracle-checkpoints/CHECKPOINT_ID/`: overall goal/North Star, authority and latest user steering, sequencing plan, original project tasklists/criteria and current status, complete project checkpoint histories, prior oracle decisions and outcomes of their assigned actions, latest compatible source/main manifest, active workers/dependencies, and observed RAM/CPU/storage/budget constraints.

Give the oracle actual access to **all checkpoint histories and the overall plan**, not just a coordinator-written favorable summary. Provide a short index highlighting changes since the prior 12-hour checkpoint; the interval's entries and unresolved/recurring findings are mandatory reading, with earlier history available for tracing patterns. Link original receipts/source evidence for consequential claims. If tool/context limits prevent access to required material, disclose the missing portion, split the reading into bounded chunks within the same invocation where supported, and do not claim a comprehensive judgment from an incomplete summary.

Record file revisions/digests and an observation cutoff so continuing project work cannot silently change what the oracle judged. Snapshot only the small control/history inputs when needed; do not copy repositories, media or raw logs for this checkpoint. Allow independent implementation to continue; a control-input cutoff is not a global source freeze. Refresh any materially changed fact before acting on a ruling, and record newer user steering that supersedes the packet.

## Ask for decisions that improve delivery

Use [the oracle prompt](assets/periodic-oracle-message.md). The oracle should compare actual history against the agreed plan and identify: stalled critical dependencies, persistent discrepancies, wasted or duplicative agent/test work, excessive coordination, resource contention, wrong sequencing, unjustified complexity/scope drift, and earlier interventions that did not work. Separate healthy waiting and legitimately revised plans from failure. Be willing to conclude that no correction is needed; do not manufacture findings to justify the cadence.

Return evidence-cited prioritized findings, distinguishing demonstrated problems from uncertainty. For each useful correction: cause, recommended decision, expected benefit/tradeoff, owning manager, bounded next action and evidence that will show it helped. Say what should continue unchanged and what truly needs user authority. A call should improve direction, not merely restate status or generate an unbounded wishlist. The oracle remains within scope, original acceptance and resource limits and does not delegate more agents.

## Act and close the loop

The orchestrator posts the ruling and concise course correction in its existing thread, then dispatches concrete in-scope actions through the owning managers. Consequential adjudication follows the designated oracle's ruling within user authority; routine ordering remains with the orchestrator. Never silently waive an acceptance gate or act on a new scope/deployment/spending request without authority. Hold only dependent work when a ruling needs clarification; keep independent work moving.

Delegate recording the packet link, invocation/result identity, actual scheduled/ad-hoc counts, ruling and action owners in status.md, and append relevant decisions to each affected project's chronological history. Do not rewrite old observations or silently replace original task criteria. The next hourly checkpoint checks action progress; the next 12-hour oracle receives whether the previous corrections helped. Mark unavailable evidence or an unimplemented ruling explicitly. Preserve reports as small local records; no raw transcript publication or new ledger duplicating project acceptance.
