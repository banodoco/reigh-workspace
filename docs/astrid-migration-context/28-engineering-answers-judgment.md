# 28 — Engineering answers: head-to-head judgment and adopted amendments

> **Status: JUDGED 2026-08-21.** This document compares `engineering-answers/A.rtf` (Response A) and `engineering-answers/message.txt` (Response B) against the ten questions in project-pack `07-questions.md`. It is an `[INFERENCE]` design judgment beneath the ratified constitution (docs 15, 24, 25 and `grok/second-opinion-decisions.md`) and does not itself outrank either the constitution or the current build contract. Adopted changes are incorporated into docs 27 and 22 and are marked **(Amended: engineering-answers judgment)**.

## 1. Decision basis

The non-negotiable tests are: local single-user operation; one Astrid SQLite authority and one managed byte tree; one same-host worker and one binding per capability; fully local generation/render; fresh start; document-native placement with one logical timeline document; and doc 27's deliberate simplicity cuts. A proposed mechanism may refine doc 27's ordering or close an omitted security/operability gap, but it may not restore cloud/fleet, plugin, second-authority, generalized event, or speculative compatibility machinery. [Docs 15, 24, 25; doc 27 §§1–3, 10]

## 3. Adopted plan decisions

1. **Atomic completion — ADOPT.** `[INFERENCE]` Verified bytes are durably installed into the hash path before `BEGIN IMMEDIATE`, using same-filesystem temp + fsync + atomic install-if-absent (or verified-existing) + parent-directory fsync. The transaction performs receipt replay first, fence validation, authoritative rows, registry merge, receipt and COMMIT. COMMIT is the only irreversible *product-state* point. Quarantine is boot-swept; CAS orphans are reported and retained until deferred GC exists. A labeled crash/IO/full-disk/retry/dedupe matrix blocks Phase B. [Amends doc 27 §§4.4, 5, 8]
2. **Falsifying slice — ADOPT.** `[INFERENCE]` The real t2i→gallery→timeline→render→Range path runs with save contention, kill/restart, lost ack, corruption, disk exhaustion, cancellation, idempotency mismatch and blocked runtime networking. A declarative fault harness and evidence table supplement, not replace, browser/editor acceptance. Thresholds begin as hypotheses and are calibrated on the floor supported tier. [Amends docs 22 Phase A; 27 §8]
3. **Document seam — ADOPT-PARTIALLY.** Add a strict `doc_format` envelope now and benchmark production-shaped size/save/merge/undo/conflict percentiles. Prune registry entries at save only after measurements identify registry growth as the constraint and tests prove the entry is unreachable from the current document and retained undo/history. Defer layered objects, overlays, chunks and paging. [Docs 24 Q1/P1; 25 #2/#3; amends doc 27 §7]
4. **Capability evolution — ADOPT-PARTIALLY.** Check in the compatible/output-determinative/public-break taxonomy, enforce doc 27 §3.2's minimal registry as a type, and land representative conformance fixtures with each capability. Keep only definition/workflow/model facts on task specs; environment facts and the executor manifest hash belong in completion provenance. Do not add plugin ABI, multiple binding, runtime conformance-result authority or version fields without a consumer. [Docs 26 D1/D3–D5; 27 §3]
5. **Model acquisition — ADOPT.** A separate, non-authoritative setup journal drives resumable download→verify→stage→atomic install→repair from a signed/versioned artifact manifest with size/hash/license/platform/tier data. Doctor owns fast/deep verification and targeted repair. Acquisition in explicit setup mode is the only sanctioned outbound networking; all task execution and Phase-A acceptance run with networking blocked. [Docs 24 Q3/P0; 25 #7; amends doc 27 §6]
6. **Wan2GP — ADOPT.** Gate every bump through hermetic rebase, contract/path/import checks, supported-platform resolution, conversion fixtures, and seeded output-shape/semantic comparison. Drain and swap the sole binding, retain a bounded prior build, record manifest provenance, and run a rollback drill in Phase B. [Doc 26 “Wan2GP update contract”; amends docs 22/27 Phase B]
7. **Orchestrators — ADOPT.** Attempt-independent child keys, pure identity/plan derivation, four-fact recovery, an explicit transition table and deterministic adversarial interleavings are Phase-B exit gates. No new kernel yield state or structural-run subsystem is added. [Docs 26 D2; 27 §§3.5, 9]
8. **Local trust — ADOPT.** The bridge adds strict loopback Host validation; a launcher-minted per-boot request token for mutation/executor authority; a custom mutation header; directories 0700 and secret-bearing files 0600 (or platform-equivalent ACLs); managed-path and archive confinement; bounded parsers/decoders; and a reviewed Comfy node allowlist for user workflows. This is a local capability check, not accounts/cloud auth. [Amends doc 27 §4 security posture]
9. **Performance — ADOPT-PARTIALLY.** Define floor and comfortable tiers, provisional p95 budgets, sustained writer occupancy `<20%`, the shared generator/journey benchmark, and local doctor diagnostics. Admission policy uses exactly `refuse` for correctness/resource impossibility, `degrade` for fidelity, and `queue` for time/capacity. Baseline evidence promotes hypotheses to release budgets. [Amends docs 22/27]
10. **Option seams — ADOPT-PARTIALLY.** Guard: stable media identity without wire paths; immutable admitted specs plus receipts/provenance; all authoritative product writes through the writer queue while only existing meaningful event boundaries remain evented; one timeline version/save route with `doc_format`; tested SQLite+managed-tree+manifest backup/restore; task ULIDs/transport-neutral wire semantics without a remote test surface; and capability conformance. Every proposed abstraction must name the row it protects; otherwise cut it. [Amends doc 27 §10]

## 4. Head-to-head judgment

**Response B (`engineering-answers/message.txt`) produced the better results overall.**

| Dimension | Winner | Why |
|---|---|---|
| Correctness depth | **B** | It turns the hardest risks into explicit state/fact sets and executable gates: DB→tree totality, four-fact orchestrator replay, transition tables, and trust controls. A is also strong, but Q1 is internally ambiguous and Q4 overclassifies output changes. |
| Ratified simplicity | **B** | B's `doc_format` seam, separate setup journal, minimal registry type, and seven-row governance add less structure than A's layered CAS objects, extra contract versions and transport/future-sync shaping. B still needs its blanket event and remote-test rows removed. |
| Actionable specificity | **B** | The five Wan gates, setup-mode network boundary, doctor repair, attempt-independent key lint, per-tier occupancy target and three degradation verbs can be assigned directly to phases and exits. |
| Gaps filled | **B** | It most clearly closes doc 27's missing local-trust contract, install/recovery contract, performance envelope and formal orchestrator exit. |
| Ceremony introduced | **B** | A introduces more speculative document/version/transport machinery. B's unnecessary runtime conformance hash, blanket event rule and non-loopback test are explicitly rejected here rather than copied into the plan. |

### Top three contributions retained from A

1. **The richer adversarial Phase-A journey:** server restart, cancel-during-publish, OS-level provider blocking, production-sized fixtures, and actual editor/browser acceptance—not only a bridge harness.
2. **The atomic lock/cleanup discipline:** in-lock work is O(stat), never O(copy), plus an orphan report and a more granular instruction-boundary crash inventory.
3. **The broader hostile-input model:** parser recursion/alias limits, archive expansion caps, media decode limits, symlink/path confinement, and an actor×vector×control×residual-risk table.
